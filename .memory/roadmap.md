# OpenDB 智能体演进路线图

## 目标
从当前的 CLI 工具箱，演进为能自动处理 99% 以上数据库问题的智能体。

## 二、DBA 工作四象限

```
            高频
            │
   日常维护 │ 性能诊断
  (统计信息、│(慢SQL、等待事件、
   空间清理) │ 会话阻塞)
            │
  ──────────┼──────────
            │
   容量规划 │ 应急处理
  (增长趋势、│(数据库挂了、空间满、
   资源预测) │ 主备切换)
            │
            低频
  不紧急 ←──────────→ 紧急
```

要覆盖 99%，每个象限都要有对应能力。

## 三、功能规划

### P0：补齐诊断深度（AI 的"眼睛"）

没有数据 AI 就无法诊断，这些是最高优先级：

| 功能 | 说明 | Skill 名 |
|------|------|----------|
| **AWR 快照分析** | 历史性能对比，回答"什么时候开始慢的" | `/awr` |
| **ASH 采样分析** | 最近 N 分钟活跃会话采样，精确定位 SQL 和等待 | `/ash` |
| **SQL 执行计划历史** | 计划变化检测（plan regression） | `/planhistory` |
| **阻塞链分析** | 锁等待完整链条（谁阻塞谁），不只是锁列表 | `/blockers` |
| **Undo/Temp 监控** | ORA-01555、temp 空间不足诊断 | `/undo`, `/temp` |
| **段级分析** | 哪个表/索引占空间最多、增长最快 | `/segments` |
| **OS 指标采集** | CPU/内存/IO/网络（v$osstat 或 OS 层） | `/os` |

### P1：补齐处理能力（AI 的"手"）

只能看不能做 = 50% 的价值：

| 功能 | 说明 | 安全级别 |
|------|------|----------|
| **收集统计信息** | `DBMS_STATS.GATHER_TABLE_STATS` | L1 操作员 |
| **参数修改** | `ALTER SYSTEM SET xxx = yyy` | L2 管理员 |
| **索引创建** | `CREATE INDEX` | L2 管理员 |
| **表空间扩容** | `ALTER TABLESPACE ADD DATAFILE` | L2 管理员 |
| **SQL Profile** | 锁定执行计划 | L2 管理员 |
| **Flush 操作** | Flush shared pool / buffer cache | L1 操作员 |
| **会话级调整** | `ALTER SESSION` 设置 trace/event | L1 操作员 |

### P2：日常维护自动化

DBA 每天重复的事，由智能体自动执行：

| 功能 | 说明 | 触发方式 |
|------|------|----------|
| **统计信息巡检** | 检测过期统计信息，自动收集 | 定时 / 检测到计划变化 |
| **空间巡检** | 表空间使用率告警，自动扩容建议 | 定时 / 阈值触发 |
| **备份巡检** | 检查最近备份状态，过期告警 | 每天 |
| **告警日志扫描** | 自动扫描 ORA- 错误，分类处理 | 定时 |
| **索引健康检查** | 碎片率、无用索引检测 | 定时 |
| **密码过期检查** | 用户密码即将过期告警 | 定时 |

### P3：高阶场景

| 功能 | 说明 |
|------|------|
| **ORA 错误知识库** | 常见 ORA 错误的自动诊断和修复方案 |
| **SQL 调优顾问** | 基于 AWR/ASH 的 SQL 自动调优 |
| **容量预测** | 基于历史趋势预测空间/CPU/内存增长 |
| **主备切换** | Data Guard switchover/failover（L3 确认） |
| **Hang 分析** | 数据库 hang 时的系统状态 dump 和分析 |
| **RAC 诊断** | 集群互联、GC 等待、实例协调 |
