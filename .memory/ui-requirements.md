# OpenDB UI/UX Requirements

## Welcome Page
- **两栏布局**: 左栏居中（欢迎文字 + DB icon），右栏左对齐（快速入门 + 已保存连接）
- **边框和线条**: 橙色（`#CC7832`），包括 `╭╮╰╯│─` 和中间分隔线
- **标题颜色**: "快速入门"、"已保存的连接" 用橙色（accentStyle）
- **DB icon**: `[=====]`（safe ASCII，避免 ambiguous-width 字符）
- **顶部无空行**: 第一行直接是 `╭─── OpenDB dev ──╮`
- **渲染方式**: 用光标绝对定位（`\033[行号;1H`），不用 `\r\n` 滚动（防空行 bug）
- **右栏内容不超宽**: 超出时自动截断加 `..`
- **不清屏**: 进入 opendb 不清屏，欢迎框紧跟在用户的命令行后面，上方 shell 历史保留可见
- **宽度安全**: 所有字符必须避免 East_Asian_Width=Ambiguous 的 Unicode 字符（`·▗▄▖▝▀▘…` 等），用 safe ASCII 替代

## Input Area (输入框)
- **跟随内容移动**: 启动时输入框在欢迎页下方，随问答向下移动
- **屏幕填满后固定底部**: 自动切换到 ANSI 滚动区域模式
- **`/clear` 重置**: 清屏后回到欢迎页下方（类似 Claude Code 压缩上下文后重置）
- **上下分隔线 + 提示符**: 上面一行 `───` 分隔线，`❯` 提示符，下面一行 `───` 分隔线（inputHeight=3）
- **启动不清屏**: 进入 opendb 不清屏，像 Claude Code 一样直接进入聊天界面
- **`/clear` 清屏**: `/clear` 时才清屏并用光标绝对定位重绘欢迎页

## Command Autocomplete (命令补全)
- **`/` 触发**: 输入 `/` 后实时显示匹配命令列表
- **Ghost text**: 第一个匹配项的补全部分以灰色显示在光标后
- **下拉列表**: 多个匹配时在输入框下方显示，最多 8 个
- **上下键选择**: 下拉列表可见时，上下键循环选择（覆盖历史翻页）
- **Tab 确认**: 按 Tab 接受选中项，自动加空格
- **ESC 关闭**: 按 Escape 关闭下拉列表
- **选中高亮**: 选中项橙色，未选中灰色
- **下拉列表不覆盖已有内容**: 下拉列表出现时必须把整体屏幕内容上移腾出空间，不能直接覆盖已有输出内容（回归 bug，已修复过一次又被覆盖）

## Command Visibility (命令可见性)
- **未登录时**: 只显示 `/login`、`/exit`、`/quit`、`/help`、`/clear`、`/config`
- **登录后**: 显示所有命令
- **原因**: 未登录时执行其他命令会报错，不应该展示

## Exit Behavior
- **`/exit` 最高优先级**: 在任何时候（包括LLM排队中）输入 `/exit` 或 `/quit` 都立即退出，不进入排队
- **不用 `os.Exit(0)`**: 否则 `defer term.Restore` 不执行，shell 会坏
- **退出不清屏**: 退出时不清屏，所有历史聊天内容保留在屏幕上，光标移到最后一行输出 "再见!"
- **退出信息**: 显示 "再见!"

## Command Queue (命令排队)
- **LLM诊断排队上限 3 个**: 诊断运行中，LLM类命令最多排队3个，超过直接拒绝（"排队已满"）
- **SQL和/命令排队可以多一些**: 非LLM命令的排队限制宽松
- **`/exit` 不排队**: 立即响应，取消所有排队

## LLM Diagnosis Output (LLM诊断输出)
- **默认 auto 模式不设限**: `DiagnoseMode=auto`, `MaxRounds=0`(即不限轮次，代码默认20)
- **逐行逐字效果**: streaming输出时，用户能看到文字逐字出现的效果
- **partial line 可见**: 未遇到换行的部分文字也要实时显示（非scroll和scroll模式都要）
- **partial line 不残留**: scroll 模式下，flush完整行前先清除partial line，防止被scroll推上去变成永久内容
- **宽度截断**: partial line 截断到终端宽度内，防止行换行造成贴图错误
- **drawInputArea 不过度**: stream delta 到达时不要每次都重绘 input area，只在 flush 完整行后才重绘
- **最终诊断必须可见**: LLM的结论必须能显示出来，不能只有"推理轮次已用完"

## Table Display (表格显示)
- **Unicode box drawing**: `┌─┬─┐│├─┼─┤└─┴─┘`，内容居中，左侧 2 空格缩进
- **智能列宽**: 总宽度不超过屏幕宽度
- **长内容截断**: 超宽字段截断并加 `...`
- **多字段溢出**: 字段太多时隐藏后面的列，最后一列标题显示 `...`
- **列转行**: 参考 MySQL `\G`，当列太多时自动转为纵向 key-value 展示，每行一个字段

## Code Block Display (代码框显示)
- **宽度适配内容**: 代码框宽度由内容决定，不拉到终端最右边
- **超宽截断**: 内容超过终端宽度时截断加 `..`，边框不能换行溢出
- **action 代码块过滤**: LLM 的 ```action 工具调用块不显示给用户
- **左侧 2 空格缩进**: 代码框整体缩进 2 格

## LLM Output Formatting (LLM输出格式化)
- **流式 Markdown 格式化**: 流式输出必须经过格式化，不能显示原始 markdown
- **标题**: `## 标题` → `■ 标题`（加粗），`### 标题` → `▸ 标题`（青色）
- **加粗**: `**文本**` → ANSI bold
- **列表**: `- 项目` → `• 项目`，`1. 项目` → 编号列表
- **行内代码**: `` `code` `` → dim 样式
- **表格**: markdown 表格转为 box-drawing 表格
- **关键词高亮**: 根因/异常（红色）、建议/优化（绿色）、指标变化（黄色）
- **最终轮不发 onRound**: 最终诊断轮不输出 "├ 第N轮: 输出最终诊断"，避免出现在分析文本之后

## Rendering Rules (渲染规则)
- **展示问题是最高优先级**: 用户最看重终端渲染效果，所有展示 bug 必须优先修复
- **全程禁止清屏**: 启动不清屏、退出不清屏、只有 `/clear` 才清屏。所有聊天历史永远保留在屏幕上
- **runewidth.EastAsianWidth = false**: 强制设置，确保宽度计算一致
- **必须在 Oracle 服务器上实测**: 不能只跑 headless 测试，必须实际验证终端渲染
- **贴图错误零容忍**: 所有边框、表格的右边框必须对齐，不能换行溢出
- **右边框不拉到最右**: 代码框、box 等的右边框适配内容宽度，不用拉到终端最右边
- **scroll 模式 partial 不覆盖已提交内容**: flush 前必须从 outputBuffer 恢复被覆盖的行
