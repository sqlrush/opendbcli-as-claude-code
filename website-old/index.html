数据库 CLI Agent

参考 Claude Code 的交互方式来管理数据库。三种交互合一 — / 命令、SQL 原生语法、自然语言 — 无需切换模式。

# 安装 (Linux / macOS)
curl -fsSL http://www.opendbcli.org/install.sh | bash
Apache 2.0 Go · 单二进制 · 零依赖 Oracle · MySQL · PostgreSQL
Sentinel 实时检测 Model 大模型诊断 Rule 规则引擎 60+ 内置技能 dbtop 秒级面板 Schedule 定时巡检

三种交互，合多为一

OpenDB 自动识别输入类型并路由到对应处理器 — 无需切换模式。

/ 简化命令

类似 Claude Code 的 /命令，把复杂运维操作整合到一个命令里。

opendb> /health
opendb> /dbtop
opendb> /slowsql 500
opendb> /llm

SQL 和原生语法

整合 sqlplus / mysql / psql 功能，直接输入 SQL。

opendb> SELECT * FROM v$session;
opendb> SHOW PARAMETER sga_target;
opendb> DESC dba_tablespaces;

自然语言

像聊天一样描述问题，AI Agent 自动分析并给出修复方案。

opendb> 数据库现在为什么慢？
⚡ 分析中... 42 个会话等待
📋 根因：SID=1842 行锁 47 分钟
🔧 ALTER SYSTEM KILL SESSION
   '1842,30721' IMMEDIATE;

特色功能

不是简单的监控告警 — 是能自主推理的数据库智能体。

功能定位一句话介绍
/health 全局体检 20+ 项指标一键扫描，7 大维度给出 ✓/⚠/✗ 状态和可操作建议
/dbtop 秒级快照 类似 Linux top，1 秒刷新 SGA/PGA/TPS/QPS/等待事件/活跃会话
/sentinel 持续监控 后台探针 48 项指标 × 9 种检测策略，自适应 3σ 基线，异常自动 Burst 采集证据
/scheduler 定时巡检 将 health / 报告 / 维护整合为 cron 定时任务，后台自动执行
/rule 规则诊断 273 条规则 × 5 阶段管线，毫秒级确定性诊断，离线可用，无需 Model
/llm AI 诊断 大模型 function calling 驱动最多 20 轮链式推理，自动采集证据，收敛到根因

真实场景 — AI 诊断输出

压测场景下的诊断输出（Claude Opus 驱动，3 轮推理，1 分 59 秒）：

opendb> /llm

  ✻ 完成 (1m 59s)
  ├ 第1轮: 调用 health (21.7s)
  ├ 第2轮: 调用 waits (1m 5s)
  ├ 第3轮: 输出最终诊断 (32.0s)

■ 问题一（严重）：序列争用 — 占总等待 70.6%

  根因: ORDER_ITEMS.ITEM_ID identity 列序列 cache 仅 20
        243.8K 次争用，累计等待 3630.7s
  证据: 51 个会话同时等待 enq: SQ - contention

  -- 立即执行:
  ALTER TABLE LOADUSER.ORDER_ITEMS
    MODIFY ITEM_ID GENERATED ALWAYS AS IDENTITY (CACHE 5000 NOORDER);

■ 问题二（重要）：Buffer Busy Waits — 占总等待 21.4%

  根因: 高并发 INSERT 竞争同一索引右侧叶子块（热块）
  证据: 223.2K 次 buffer busy waits，累计 1098.9s

■ 问题三（严重）：Redo 日志切换过频

  根因: 3 组 × 200MB redo，1 小时切换 162 次（22 秒/次）

  ALTER DATABASE ADD LOGFILE GROUP 4 SIZE 1G;
  ALTER DATABASE ADD LOGFILE GROUP 5 SIZE 1G;
  ALTER DATABASE ADD LOGFILE GROUP 6 SIZE 1G;

规则引擎 — 毫秒级诊断

273 条规则 × 5 阶段管线，离线可用。真实压测场景下 2.7 秒完成诊断：

opendb> /rule

  根因: 序列 CACHE 过小或 NOCACHE 导致 SQ 争用
  严重程度: ■■■□ 高    置信度: 78%

  ── 证据链 ──
  1. enq: SQ - contention 由序列 CACHE 值过小引起
  2. 每次 CACHE 用完需更新 seq$，引发 row cache lock
  3. 高并发 INSERT 使用 NOCACHE 序列时尤为严重

  ── 处置建议 ──
  [紧急] 查看争用序列并增大 CACHE
  [修复] 查看 ASH 确认争用序列对象
  [预防] 考虑 UUID 或应用层生成 ID

  ── 关联分析 ──
  • cursor: pin S — 下游症状，解决根因后同步缓解
  • buffer busy waits — 下游症状，解决根因后同步缓解

快速开始

一键安装

curl -fsSL http://www.opendbcli.org/install.sh | bash

安装向导会引导你完成数据库连接和 Model 配置。

从源码编译

git clone https://github.com/sqlrush/opendb.git
cd opendb && make build
./bin/opendb --setup
