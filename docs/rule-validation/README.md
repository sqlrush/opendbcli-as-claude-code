# Rule Engine 验证与优化策略

## 目标

通过 Opus 做裁判，系统化验证和优化 Rule Engine 的诊断能力，使 Rule 输出达到 Opus 90% 的相似度。

## 核心流程

```
┌─────────────────────────────────────────────────────────────────┐
│                     一轮验证周期                                  │
│                                                                 │
│  1. 模拟故障 ──→ 2. 采集数据 ──→ 3. Rule 诊断 ──→              │
│                                    Opus 诊断 ──→                │
│  4. Opus 比对打分 ──→ 5. 输出优化方案 ──→ 6. 执行优化           │
│                                                                 │
│  重复直到 Opus 打分 ≥ 90 分                                     │
└─────────────────────────────────────────────────────────────────┘

达到 90% 后 ──→ 生成新场景 ──→ 进入下一轮
```

## 详细步骤

### Step 1: 模拟故障
- 在测试服务器（47.88.57.91）上用 SQL/Shell 真实制造故障
- 确认故障指标达到预期值（sentinel 触发或手动确认）
- 记录故障现场快照

### Step 2: 分别诊断
- **Rule 诊断**: 调用 `/rule live` 获取 rule engine 输出
- **Opus 诊断**: 将相同的监控数据交给 Opus，独立分析给出标准方案

### Step 3: Opus 比对打分
- Opus 对比两个方案，按 5 个维度打分（满分 100）：
  - 根因识别（40 分）
  - 修复建议（30 分）
  - 严重程度（10 分）
  - 排查路径（10 分）
  - 完整性（10 分）
- 输出扣分原因和具体优化方案

### Step 4: 汇总结果
- 100 个场景的结果汇总到 `results/round-N-scores.md`
- 超大表格：场景 | Rule评分 | 扣分原因 | 优化方案

### Step 5: 执行优化
- 按评分从低到高排序，优先优化得分最低的场景
- 修改对应的 JSON 规则或 Go 规则代码
- 优化记录写入 `improvements/round-N-changes.md`

### Step 6: 回归验证
- 优化完成后重新跑一轮全量测试
- 对比前后评分变化
- 重复直到平均分 ≥ 90

### Step 7: 扩展场景
- 平均分达到 90% 后，生成新的更难场景
- 进入下一轮验证周期

## 评分标准

| 维度 | 权重 | 说明 |
|------|------|------|
| 根因识别 | 40 分 | 是否找对根本原因 |
| 修复建议 | 30 分 | SQL/操作是否正确可执行 |
| 严重程度 | 10 分 | 是否正确评估紧急性 |
| 排查路径 | 10 分 | 诊断步骤是否合理高效 |
| 完整性 | 10 分 | 是否遗漏关键信息 |

## 退出条件

- **当轮退出**: 100 个场景平均分 ≥ 90
- **整体退出**: 连续两轮新场景平均分 ≥ 90

```

├── README.md                          ← 本文件（策略说明）
├── oracle-100-scenarios.md            ← 100 个 Oracle 故障场景清单
├── oracle/                            ← Oracle 故障模拟脚本
│   ├── T001_simulate.sql              ← 模拟脚本
│   ├── T001_cleanup.sql               ← 还原脚本
│   └── ...
├── results/                           ← 每轮验证结果
│   ├── round-1-scores.md              ← 第 1 轮评分表格
│   ├── round-2-scores.md              ← 第 2 轮评分表格
│   └── ...
└── improvements/                      ← 每轮优化记录
    ├── round-1-changes.md             ← 第 1 轮改了哪些规则
    ├── round-2-changes.md             ← 第 2 轮改了哪些规则
    └── ...
```

## 适用范围

- **第一阶段**: Oracle（100 个场景）
- **后续阶段**: MySQL / PostgreSQL / OpenGauss（复用相同流程）
